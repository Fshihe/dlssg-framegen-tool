# DLSSG 帧生成 一键开启工具

给 **RTX 20 / 30 系列**显卡一键开启 DLSS 帧生成（Frame Generation）的图形化小工具。

底层使用 [sdli1995/dlssg_for_sm86](https://github.com/sdli1995/dlssg_for_sm86)（DLSSG Native 0.2.4）。
本工具负责把这件事变成点一下按钮：**自动识别你的显卡该用哪条计算路由、自动找到游戏真正的渲染主程序、自动备份与还原。**

> **单个 exe，39 MB，无需安装、无需 Python、无需联网。** 去 [Releases](../../releases) 下载。

## 实机验证状态

这类工具最怕「作者说能用，你装上不好使」。所以先把验证情况摊开讲：

| 计算路由 | 显卡 | 验证情况 | 结果 |
|---|---|---|---|
| **SM86** | RTX 3070（Ampere） | 真机实测 | ✅ 帧生成成功开启 |
| **SM75** | RTX 2070 Laptop（Turing） | 真机实测 | ✅ 帧生成成功开启 |

- 测试游戏：《黑神话：悟空 性能测试工具》（D3D12 + 自带 Streamline/DLSSG 插件栈）
- 两台机器开启后**均未观察到画面异常**（无闪烁、无拖影、无错误帧）
- 验证方式：Mod 诊断日志确认 `ngx_driver_connected` + `feature_id:11`（= 帧生成特性），
  且 `runtime_redirect` 显示已成功劫持游戏对 `nvngx_dlssg.dll` 的加载请求
- 详细证据与排查过程见 [docs/测试报告.md](docs/测试报告.md)

### 实测帧率参考

| 显卡 | 倍率 | 开启前平均 | 开启后平均 | 提升 |
|---|---|---:|---:|---:|
| RTX 3070（Ampere） | 3X | 41 FPS | **105 FPS** | **+156%** |
| RTX 2070 Laptop（Turing） | 2X | 40 FPS | **65 FPS** | **+62.5%** |

> ⚠️ 这是**单个游戏（《黑神话：悟空 性能测试工具》）、单次实测**的数据，只用来感受量级，
> **不要当预期值**。不同游戏、画质、分辨率下的差异可能非常大。
> 倍率一列是按实测帧率反推的（见 [测试报告](docs/测试报告.md) 中的验算），非用户填写。
>
> 帧生成是拿 GPU 算力换帧数 —— 卡越弱，插帧本身的相对开销占比越大，净增幅越小：
> 2070 的插帧开销约 5.8 ms，3070 约 4.2 ms，正好印证了这一点
> （2070 更弱，且 SM75 走的是未深度优化的独立内核路径）。
> 反过来，显卡越强也越容易被 CPU 或游戏引擎本身卡住上限，增幅不一定线性增长。

> **SM75 这一条值得单独说**：上游 README 自己写着「SM75 路由已在 3080 Ti 上完成前向
> PTX 检查；**物理 Turing/Cubin 仍待验证**」。也就是说连上游作者都没在真实 20 系显卡上
> 跑过。本项目的 RTX 2070 实测补上了这个空白。

## 它解决什么问题

上游 Mod 本身是「手动挡」，你要自己完成三件事：

1. 判断自己的显卡该用 `Router=SM86`（30 系）还是 `SM75`（20 系）
2. 手写 `dlssg_sm86.ini`
3. **在游戏目录里翻出真正的渲染 EXE** ——
   像 `…\b1\Binaries\Win64\b1-Win64-Shipping.exe` 这种路径，
   放到启动器目录或 `Engine` 目录都是**完全不生效**的

第 3 步是新手最容易栽的地方：文件放错了，游戏照常启动、毫无提示、Mod 静默失效。

本工具把这三步全部自动化，并且把「改坏电脑」的可能性堵死。

## 三步使用

### ① 看环境

打开工具，它自动读出显卡型号、驱动版本、显存，并给出结论：

- `✓ 你的显卡可以用` → 继续
- `⚠ 不需要这个工具`（RTX 40/50 系）→ 你的卡原生支持帧生成，游戏里直接开就行
- `✗ 显卡不受支持`（GTX 16 系 / 10 系 / A 卡）→ 硬件上做不到

**同时检查「硬件加速 GPU 计划（HAGS）」** —— 见下方专节，这一步不能跳。

### ② 选游戏

自动扫描 Steam / Epic / GOG 游戏库，列出所有游戏并标出哪些能开（★ = 64 位 + D3D12）。
也可以点「浏览游戏文件夹…」手动指定。选中后它会自动定位主程序，并**把判断依据列给你看**
（哪一项导入表证明了它是 D3D12、同目录有没有 `nvngx_dlssg.dll`）。

### ③ 点「一键安装」

先跑一遍预检并把要做的改动列给你确认，然后执行。

装完**完全退出游戏再重启**，在画面设置里打开「帧生成 / Frame Generation」，选 2X / 3X / 4X。

## ⚠ 如果游戏提示「您的显卡不支持 DLSS 帧生成技术」

**先查这一项：硬件加速 GPU 计划（HAGS）。**

DLSS 帧生成不只看显卡，还硬性依赖操作系统的「硬件加速 GPU 计划」。
这一项关闭时，**即使 RTX 40 系也用不了帧生成**，而游戏只会给你一句
「您的显卡不支持 DLSS 帧生成技术」—— 极容易被误判成 Mod 没生效。

这一点不是理论：开发过程中在 RTX 3070 上实测时，Mod 日志已经显示成功连上 NGX
帧生成特性、也成功劫持了 `nvngx_dlssg.dll` 的加载，但游戏依然弹这个框 ——
根因就是 HAGS 被关掉了。开启后即正常。

工具会自动检测：

- **图形界面**：环境面板红字提示，右边有「开启硬件加速 GPU 计划」按钮
- **命令行**：`DLSSG帧生成一键开启工具.exe hags`
- **预检**：`check` 命令的输出里会明确列出

开启方式（任选其一，**改完必须重启电脑**）：

1. 工具里的「开启硬件加速 GPU 计划」按钮
2. 设置 → 系统 → 屏幕 → 显示卡 → 更改默认图形设置 → 硬件加速 GPU 计划
3. 命令行：`DLSSG帧生成一键开启工具.exe hags --enable -y`（需管理员）

### 其他排查顺序

1. **游戏是否在运行** —— 装完必须完全退出游戏再重启，不是重开一局
2. **把日志级别改成「运行诊断（Level=2）」重装一次**，进游戏后看
   `<游戏目录>\dlssg_sm86\logs\native_<PID>.jsonl`：
   - 有 `ngx_driver_connected` + `feature_id:11` → Mod 已正常接入
   - 有 `runtime_redirect` → 已成功劫持游戏对 `nvngx_dlssg.dll` 的加载请求
   - **完全没有日志目录** → 游戏没加载这个代理 DLL，换个代理入口试试
     （选项里「代理入口」从「自动选择」改成 `winmm.dll`）重新安装
3. **确认游戏本身提供帧生成选项**。工具详情面板会显示同目录是否有
   `nvngx_dlssg.dll` / `sl.dlss_g.dll`（游戏原生支持帧生成的标志）。
   如果游戏压根没带这个功能，Mod 也变不出来 ——
   **优先选游戏设置里已经能看到「帧生成」选项的**（哪怕灰着点不动）
4. **显存不足**也可能导致选项不可用或开启后卡顿

一键取证：`DLSSG帧生成一键开启工具.exe collect "<游戏目录>"`
会把环境、安装状态、INI 内容和 Mod 日志打包成一个 txt，方便贴出来求助。

> 想反馈某个游戏能不能用？见 [docs/兼容性反馈指南.md](docs/兼容性反馈指南.md) ——
> 里面有反馈模板和「怎么自己看 Mod 日志」的对照表。你的一次测试能帮到后面所有人。

## 支持的显卡

| 显卡 | 架构 | 计算路由 | 是否可用 |
|---|---|---|---|
| RTX 3050 / 3060 / 3070 / 3080 / 3090 及 Ti、Laptop 版 | Ampere (SM86) | `Router=SM86` | ✅ 已实测 |
| RTX A2000 / A4000 / A5000 / A6000 | Ampere (SM86) | `Router=SM86` | ✅ 理论支持 |
| RTX 2060 / 2070 / 2080 及 Super / Ti、Laptop 版 | Turing (SM75) | `Router=SM75` | ✅ 已实测 |
| Quadro RTX、TITAN RTX | Turing (SM75) | `Router=SM75` | ✅ 理论支持 |
| RTX 40 / 50 系列、RTX PRO | Ada / Blackwell | — | ⚠ 原生支持，不需要本工具 |
| GTX 16 系列 | Turing（无 Tensor Core） | — | ❌ 硬件不支持帧生成 |
| GTX 10 系列及更早、AMD、Intel | — | — | ❌ |

**游戏要求**：Windows 10/11 x64、**Direct3D 12**、且游戏自身提供帧生成选项。
Vulkan 游戏当前版本不支持（上游列在下一版计划里）。

「理论支持」= 型号识别与配置生成已通过测试，但没有对应硬件的实机验证。

### 显存提醒

插帧会额外占用显存。上游在 RTX 3080 Ti 上的参考值（按最终**输出分辨率**选行）：

| 输出分辨率 | 2X | 3X | 4X |
|---|---:|---:|---:|
| 1080p | 约 320 MiB | 约 330 MiB | 约 340 MiB |
| 2K / 1440p | 约 490 MiB | 约 510 MiB | 约 520 MiB |
| 4K | 约 700 MiB | 约 740 MiB | 约 770 MiB |

显存吃紧时会出现偶发卡顿，即使平均帧率看着正常。建议留出高于上表的余量。

## 安全设计

这是本工具最花心思的部分。以下每一条都有自动化测试覆盖（内置「安全自检」按钮，**85 项**）。

| 承诺 | 实现方式 |
|---|---|
| **只写两个文件** | 全流程只会向游戏目录写入 `<代理>.dll` 和 `dlssg_sm86.ini`，一个字节都不多写 |
| **不碰系统** | 不写注册表、不装驱动、不改系统设置、不动杀软、不改 PATH、不建服务 |
| **覆盖前必先备份** | 任何被覆盖的同名文件先复制到 `%LOCALAPPDATA%\DLSSG-SM86-Tool\backups\`，备份后立即校验 |
| **写入即校验** | 每个文件落盘后核对 SHA256，不一致立刻中止 |
| **失败必回滚** | 中途任何一步出错，游戏目录逐字节恢复到安装前状态（含已写入的、已删除的文件） |
| **原子写入** | 先写临时文件再原子替换，断电也不会留下半个文件 |
| **卸载完整还原** | 删除本工具的文件，并把安装前被覆盖的原文件放回去，同时清掉 Mod 运行日志目录 |
| **不误删你的东西** | 卸载时只删哈希与安装记录一致的文件；你手改过的文件会被保留并提示 |
| **拒绝在游戏运行时安装/卸载** | 避免文件占用与污染运行中的进程；删除失败时**不谎报成功** |
| **反作弊拦截** | 检测到 EasyAntiCheat / BattlEye / Vanguard / ACE 等一律默认阻止 |
| **DLL 完整性基线** | 内置 5 个 DLL 的 SHA256，安装前逐个核对，损坏或被篡改就拒绝安装 |
| **无需管理员权限** | 游戏目录可写就不提权；确实需要时才提示以管理员身份重启 |
| **状态丢失也能收拾** | 就算安装记录被清掉，也能按内置哈希认出本工具放的文件并干净卸载 |

**唯一会永久留下的东西**：`%LOCALAPPDATA%\DLSSG-SM86-Tool\` 下的日志、状态与备份。
删掉这个文件夹就等于彻底清除本工具的一切痕迹（不影响已安装的游戏文件）。

**关于「不改注册表」**：安装/卸载游戏文件的流程完全不动注册表。唯一例外是你**主动点击**
「开启硬件加速 GPU 计划」时，工具才会修改**一个**值
（`HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers\HwSchMode`，1 → 2），
这与 Windows 设置界面里的开关是同一件事，点击前会弹出说明让你确认。

## ⚠️ 免责声明（请务必阅读）

1. **反作弊与封号风险**：本工具通过系统 DLL 代理 + LoadLibrary hook 的方式接入游戏。
   **给带反作弊的联机游戏使用有封号风险。** 工具会扫描游戏目录与运行中的反作弊服务，
   命中即默认阻止安装；如果你强行继续，风险自负。**建议只用于单机游戏。**

2. **杀软误报**：这类接入方式会被启发式引擎误报，**这是上游 Mod 的固有特性**。
   上游 5 个 DLL 都带自签名证书（`CN=DLSSG Native Project (Self-signed)`），
   可在文件属性 →「数字签名」中查看。自签名不提供 Windows 默认信任，仍可能有
   SmartScreen 提示。本工具自身**没有做任何压缩加壳**（不用 UPX），以降低误报率。

3. **不保证可用性**：帧生成的实际效果取决于游戏、驱动、系统配置和显卡本身。
   上游项目存在崩溃、闪烁、显存溢出等已知问题报告。
   **本工具按「现状」提供，不对任何特定游戏或硬件组合的可用性作保证。**

4. **备份你自己的存档**：虽然本工具只写游戏目录里的 2 个文件、且卸载可完整还原，
   但为防万一，重要存档建议先自行备份。

5. **使用本工具即表示你已知悉上述风险并自行承担后果。**

## 命令行用法（可选）

同一个 exe 也能当命令行工具用：

```bat
DLSSG帧生成一键开启工具.exe detect              检测显卡环境
DLSSG帧生成一键开启工具.exe list --d3d12        列出可开启帧生成的游戏
DLSSG帧生成一键开启工具.exe inspect "<目录>"    分析某个游戏目录
DLSSG帧生成一键开启工具.exe check   "<目录>"    安装前预检
DLSSG帧生成一键开启工具.exe plan    "<目录>"    预演（不写入任何东西）
DLSSG帧生成一键开启工具.exe install "<目录>" -y 直接安装
DLSSG帧生成一键开启工具.exe verify  "<目录>"    安装体检
DLSSG帧生成一键开启工具.exe uninstall "<目录>"  卸载并还原
DLSSG帧生成一键开启工具.exe hags                检查硬件加速GPU计划
DLSSG帧生成一键开启工具.exe collect "<目录>"    收集诊断包（求助用）
DLSSG帧生成一键开启工具.exe selftest            运行内置安全自检（85 项）
DLSSG帧生成一键开启工具.exe report              生成环境报告
```

常用参数：`--router SM86|SM75|auto`、`--proxy winmm.dll`、`--bilinear 0|1`、
`--log-level 0..3`、`--dry-run`、`-y`。

> 提示：从 cmd 运行时，Windows 不会等待 GUI 子系统的程序，输出可能出现在提示符之后，属正常现象。

## 从源码构建

```bat
:: 1. 取上游代理 DLL（会自动校验 SHA256）
python tools\fetch_payload.py

:: 2. 打包
python build.py            :: 完整版：内置全部 5 个代理 DLL，离线可用
python build.py --slim     :: 精简版：只内置 version.dll
python build.py --no-verify
```

构建脚本会自动：校验 payload 哈希 → 生成图标 → PyInstaller 打包 → 对产物跑一遍内置自检。

源码直接运行（不打包）：

```bat
set PYTHONPATH=src
python src\main.py              :: 图形界面
python -m dgcore.selftest       :: 85 项自检
python tools\check_sm75.py      :: RTX 20 系列（SM75）路径验证
```

依赖：**仅 Python 标准库**（tkinter 随 Python 自带）。打包需要 `pyinstaller`。

## 卸载

1. 在工具里对每个装过的游戏点「卸载并还原」，或
   `DLSSG帧生成一键开启工具.exe uninstall "<游戏目录>"`
2. 想彻底清除工具痕迹：删掉 `%LOCALAPPDATA%\DLSSG-SM86-Tool\` 整个文件夹。

也可以按上游文档手动卸载：退出游戏，删掉游戏目录里的 `<代理>.dll` 和 `dlssg_sm86.ini`。

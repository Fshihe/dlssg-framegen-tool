# 兼容性反馈

这个工具能不能用，主要看游戏自己有没有帧生成功能。各游戏差别很大，
我手上只有一个游戏，所以别人的测试结果很有用。

## 反馈之前先自己排查三步

1. **硬件加速 GPU 计划开了吗**
   帧生成必须开着这个。工具环境面板会显示状态，红字就是没开。
   大部分「提示显卡不支持」都是这个原因。

2. **游戏完全退出了吗**
   要整个退出进程再启动。回主菜单重开一局不算。

3. **游戏本身有这个选项吗**
   进画面设置看看有没有「帧生成 / Frame Generation」。
   本来就能看到（哪怕灰着点不动）的成功率最高。压根没做这个功能的游戏，工具也没办法。

   工具现在会在详情面板里直接告诉你判断结果，装之前就能看到。

## 取证

```
dlssg-cn.exe collect "游戏目录"
```

会生成一个 txt 在 `%LOCALAPPDATA%\DLSSG-SM86-Tool\reports\`，
里面有显卡和系统环境、HAGS 状态、安装状态、用的哪个上游版本、ini 内容、还有 Mod 的运行日志。

把这个文件贴出来比写一堆文字描述有用得多。

## 反馈格式

懒得写就按这个填：

```
显卡：
驱动版本：
硬件加速 GPU 计划：开了 / 没开
Windows 版本：

游戏名：
上游版本（工具里会显示）：0.2.4 / 0.3.0
游戏设置里原本能看到帧生成选项吗：能看到（灰的）/ 看不到 / 没注意

结果：成功 / 选项出现了但点不动 / 选项没出现 / 游戏崩溃
帧率：从 ___ 到 ___
画面：正常 / 轻微闪烁拖影 / 明显异常（描述一下）

诊断包内容贴在下面：
```

## 自己看日志

日志在 `<游戏目录>\dlssg_sm86\logs\`，需要安装时把日志级别设成 2 才会写。

注意 0.2.4 和 0.3.0 的日志文件名不一样：

| 版本 | 日志文件 |
|---|---|
| 0.2.4 | `native_<PID>.jsonl` |
| 0.3.0 | `loader_*.jsonl`、`backend_*.jsonl` |

| 日志里出现 | 说明 |
|---|---|
| `ngx_driver_connected` 带 `"feature_id":11` | 连上 NGX 帧生成了（11 就是帧生成） |
| `runtime_redirect` | 成功劫持了游戏对 `nvngx_dlssg.dll` 的加载 |
| `route active=true` | 0.3.0 的内核路由已激活 |
| **完全没有日志目录** | 游戏没加载这个代理 dll，换个入口试试 |

要说清楚的是：日志正常**不代表游戏一定会显示帧生成选项**。
游戏可能有自己的判断。Mod 日志正常但游戏不给选项的情况，正是最需要收集的。

## 20 系特别说明

如果你是 RTX 20 系列，工具会自动用 **0.2.4** —— 因为上游 0.3.0 已经移除了 SM75 内核。

这条路径属于**实验性支持**。已知情况：

- 本项目的 RTX 2070 笔记本实测正常（40 → 65 FPS，无画面异常）
- 但 20 系玩家反馈里有若干「画面闪烁」的案例

如果遇到闪烁，请带上诊断包反馈并说明游戏名 —— 这类信息对判断
「是 SM75 内核的问题还是特定游戏的问题」很关键。

## 已知不能用的

不用反馈了：

- GTX 16 系、10 系及更早、A 卡、核显 —— 硬件不支持帧生成
- RTX 40/50 系 —— 本来就能开，用不着这个工具
- Vulkan 游戏 —— 现在只支持 D3D12
- 带反作弊的联机游戏 —— 工具会主动拦下来
